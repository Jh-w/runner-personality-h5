## 2. 5维计分引擎设计

### 2.1 新增 Expression 维度

| 属性 | 值 |
|------|-----|
| 维度 key | `'expression'` |
| 中文名 | 表达方式 |
| 左极（< 0） | D — 数据派 (Data-driven) |
| 右极（≥ 0） | A — 氛围派 (Atmosphere-driven) |
| 分值范围 | 每题 ±1 或 ±0.5，3题累加 |
| 判定规则 | 总分 < 0 → D / ≥ 0 → A |

### 2.2 5位编码规范

```
位置1 (motivation):  < 0 → 'C' (竞技) | ≥ 0 → 'E' (体验)
位置2 (social):      < 0 → 'S' (独狼) | ≥ 0 → 'G' (社群)
位置3 (style):       < 0 → 'D' (计划) | ≥ 0 → 'P' (随性)
位置4 (ritual):      < 0 → 'G' (装备) | ≥ 0 → 'M' (极简)
位置5 (expression):  < 0 → 'D' (数据) | ≥ 0 → 'A' (氛围)  🆕
```

示例: `CSGP_D` = 竞技·独狼·社群·计划·数据派（注意位置2和位置3容易混淆——位置2是social（S=独狼/G=社群），位置3是style（D=计划/P=随性），位置5是expression（D=数据/A=氛围））

### 2.3 计分逻辑

```
calculateScores(18个答案) → DimensionScores {
  motivation:  number  // Q1+Q2+Q9 累加
  social:      number  // Q3+Q4+Q10 累加
  style:       number  // Q5+Q6+Q11 累加
  ritual:      number  // Q7+Q8+Q12 累加
  expression:  number  // Q13+Q14+Q15 累加  🆕
}

signKey(scores) → "CSGP_D"  // 5字母编码
                → lookup 32型映射表
                → PersonalityTypeId (1-32)
```

风味标签**独立判定**，不参与 signKey 和 typeId 计算：

```
flavorScore(answers) → FlavorScores {
  time:    'morning' | 'night' | 'flexible' | 'anytime'
  injury:  'panic' | 'careful' | 'ignore' | 'listen'
  diet:    'fuel' | 'reward' | 'balance' | 'whatever'
}
```

### 2.4 signKey 函数改造（伪代码）

```typescript
// v4.1（4维）
function signKey(scores: DimensionScores): string {
  const c1 = scores.motivation < 0 ? 'C' : 'E';
  const c2 = scores.social < 0 ? 'S' : 'G';
  const c3 = scores.style < 0 ? 'D' : 'P';
  const c4 = scores.ritual < 0 ? 'G' : 'M';
  return `${c1}${c2}${c3}${c4}`;
}

// v4.3（5维）
function signKey(scores: DimensionScores): string {
  const c1 = scores.motivation < 0 ? 'C' : 'E';
  const c2 = scores.social < 0 ? 'S' : 'G';
  const c3 = scores.style < 0 ? 'D' : 'P';
  const c4 = scores.ritual < 0 ? 'G' : 'M';
  const c5 = scores.expression < 0 ? 'D' : 'A';  // 🆕
  return `${c1}${c2}${c3}${c4}_${c5}`;            // 🆕 下划线分隔
}
```

### 3.2 风味题数据结构

风味的 `Question.dimension` 字段需要扩展：

```typescript
// v4.1
```

建议：风味题在 `Question` 中用新字段 `flavorDimension?: FlavorDimension` 标记，不污染 `dimension` 字段。

### 3.3 score 扩展

计分引擎处理时：

```typescript
// 风味题跳过 dimensionScore 累加
for (const answer of answers) {
  const dim = questionDimensionMap[answer.questionId];
  if (dim) {
    scores[dim] += answer.dimensionScore;
  }
  // 风味题 answer.questionId >= 16 → 不进入 dimensionScore 累加
}
```

### 5.2 引用方式

```typescript

// 或运行时动态构建
const animalImg = `/runner-personality-h5/animals/animal-type-${String(typeId).padStart(2, '0')}.png`;
```

v4.2.5 已实现第一种方式（personalities.ts 中每个类型硬编码 `animalImg`），v4.3 继续使用。

### 5.3 Fallback 机制（已有，复用）

`TypeIllustration` 组件已实现三级降级：

1. **优先**：加载 `animalImg` 静态PNG → `<img src={animalImg} />`
2. **降级1**：PNG加载失败 → 显示 `animalEmoji` + 人格色圆形背景
3. **降级2**：无 animalEmoji → 返回 `null`

```typescript
// TypeIllustration.tsx（现有实现，直接复用）
if (animalImg && !imgError) {
  return <img src={animalImg} onError={() => setImgError(true)} />;
}
if (animalEmoji) {
  return <div style={{ background: colorBg }}><span>{animalEmoji}</span></div>;
}
return null;
```

## 8. 去编码化设计

### 8.1 原则

> **编码（CSGP_D 等）只在 engine 层存在，不暴露给任何 UI 组件。**

### 8.2 分层约束

| 层级 | 允许使用编码？ | 数据传递方式 |
|------|:---------:|------------|
| `engine/types.ts` | ✅ 定义和使用 | 类型系统 |
| `engine/personalities.ts` | ✅ 作为 Record key | 内部 |
| `engine/scoring.ts` | ✅ 产出生编码 | signKey() 返回值 |
| `engine/flavorScoring.ts` | ❌ 不需 | N/A |
| `hooks/useTestEngine.tsx` | ❌ 不碰 | 只传 typeId |
| `pages/ResultPage.tsx` | ❌ 禁止 | 通过 `getPersonalityByTypeId(typeId)` |
| `components/CanvasRenderer.tsx` | ❌ 禁止 | 接收 PersonalityResult，用 `.name` `.animalImg` |
| `components/TypeIllustration.tsx` | ❌ 禁止 | 用 `animalImg` prop |
| `utils/typeColorMap.ts` | ⚠️ 内部映射 | 输入 code，输出 CSS 变量（编码不泄露到 DOM） |

### 8.3 关键检查点

- 分享卡片 Canvas 渲染文本中不含编码
- `personality.code` 字段存在但 UI 永不读取展示
- 雷达图、标签、分享文案均不引用编码
- URL 中 `typeId` 为数字（如 `/result/1`），不含编码

## 9. 风味标签系统

### 9.1 独立判定逻辑

风味标签与32型人格分类**完全独立**：

```
用户答题流程:
  Q1-Q15  → 计分引擎 → 5维得分 → 32型人格
  Q16-Q18 → 风味引擎 → 3维标签 → 风味卡片

两者互不干扰，Q16-Q18 不影响 32 型分类结果
```

### 9.2 风味计分引擎

```typescript
// engine/flavorScoring.ts 🆕

export function calculateFlavorScores(answers: Answer[]): FlavorScores {
  const flavorAnswers = answers.filter(a => a.questionId >= 16 && a.questionId <= 18);
  
  // Q16 = time, Q17 = injury, Q18 = diet
  // 每题直接取 flavorValue（如 'morning'）
  const result: FlavorScores = { time: '', injury: '', diet: '' };
  
  for (const a of flavorAnswers) {
    const q = getQuestionById(a.questionId);
    if (q?.flavorDimension) {
      const option = q.options.find(o => o.id === a.optionId);
      result[q.flavorDimension] = option?.flavorValue || '';
    }
  }
  
  return result;
}
```
